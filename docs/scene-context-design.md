> 决策记录见 [§8](#8-已确认的决策)。

## 1. 为什么需要这一层：三条实测依据

### 1.1 pd4 上一个真实场景被建出 45 条 track，其中 9 条判 DANGER

`person_falldown-4.mp4`（最难的真实素材）逐 track 诊断结果：

| track | 最后一次框 | DANGER 帧 |
|---|---|---|
| 3 | (675,653,855,1008) 180×355 | 112 |
| 6 | (705,418,900,607) 195×189 | 253 |
| 10 | (465,485,1031,929) 566×444 | 149 |
| 14 | (201,739,687,1022) 486×283 | 64 |
| 18 | (250,438,531,805) 281×367 | 176 |
| 20 | (1233,810,1366,1024) 133×214 | 40 |
| 21 | (674,575,873,751) 199×176 | 259 |
| 28 | (25,638,187,1077) 162×439 | 121 |
| 30 | (505,334,744,930) 239×596 | 26 |
| **合计** | **45 条 track** | **1200 帧** |

首个 DANGER：帧 107，track 3，bbox `(421,550,788,893)` —— **是那辆电瓶车的位置**。

场景里真实物体约 6 个（3–4 辆停放电动车 + 1 棵树 + 1–2 个人），系统却建了 45 条 track。
**pd4 现在能报警，是"一堆假轨迹里恰好有一条盖在老人附近"，不是识别出了跌倒。**

### 1.2 停放的电动车比真人"更像人"

| 对象 | bbox score | 关键点均值 | 有效关键点 |
|---|---|---|---|
| 盖蓝车罩的电动车 | 0.024–0.088 | **0.71–0.86** | **16–17 / 17** |
| 真人（同场景路人） | 0.237 | 0.42–0.47 | 10 |
| 树 | 0.087 | 0.39 | **6**（通过 `min_valid_kpts=4`） |

`select_person` 按 `Σkpts_conf` 取最大 → **永远选到车**。这是
[pose_extractor.py:204](../pose/pose_extractor.py) 已记录的已知缺陷。

### 1.3 "提高阈值"和"合并重复框"在数学上不可行

- 假框 score **0.028–0.088**，躺地老人 **0.024–0.054** → **完全重叠**，提 `conf` 会连人一起杀
- 额外框与主框 IoU 中位 **0.000**、0% 可被现有合并逻辑合并（包含度最大 0.599，差 0.001 过不去）

### 1.4 结论

现有链路里，**判断"是不是人"只有两处可用信息**：bbox score 和关键点统计量。
而这两者在真人与车罩之间不可分（1.3）。因此必须引入**新的信息维度**：

| 维度 | 现状 | 本设计 |
|---|---|---|
| 外观（颜色/纹理） | ❌ 完全没有 | anchor 与候选都带 |
| 形状（宽高比/填充率） | ❌ 64 维里没有 bbox 尺寸 | anchor 与候选都带 |
| 场景关系（在路中间/车旁） | ❌ 刻意丢弃（[architecture.md §9.6](architecture.md)） | anchor 层提供 |
| 运动 | ✅ 已在 `vel`/`acc` 里，但未被当作身份判据 | unit 级聚合 |

## 2. 设计目标

| # | 目标 | 量化 |
|---|---|---|
| 1 | 压制假目标 | pd4 的 track 数 **45 → ≤ 8**；非人素材每帧假 track 数下降 ≥ 50% |
| 2 | 保住躺地老人 | pd4 跌倒段（帧 140–260）内**至少一个 unit 判为人** |
| 3 | 不推迟报警 | 首 DANGER ≤ 107 帧（生产基线） |
| 4 | 不引入假报警 | 正常 Le2i 7 段 WARNING/DANGER 全 0 |
| 5 | 可实时 | 总延迟 ≤ 40 ms（25 fps） |
| 6 | **不重训** | 层 0–2 为检测/规则层，不改分类器输入 |

## 3. 架构

```
┌─ 层 0 · 场景普查（每 5 帧一次）────────────────────────────┐
│  YOLO-World（开放词表）                                     │
│  词表：person / person lying on the ground /                │
│        person sitting on the ground / person walking /      │
│        road / sidewalk / tree / motorcycle / bicycle / wall │
│  → anchor 集合 A = {类别, bbox, 帧内位置, 颜色统计, 形状}    │
│  静止 anchor 可缓存，不必每帧重算外观                        │
└────────────────────────────────────────────────────────────┘
                        │
┌─ 层 1 · 候选（每帧）──────────────────────────────────────┐
│  YOLO-Pose conf=0.02 → 候选框 + 17 关键点                   │
│  分档：                                                     │
│    · 与 anchor 语义一致且分数高 → 直接信任                   │
│    · 低分 / 与 anchor 冲突      → 进入层 2 待判              │
└────────────────────────────────────────────────────────────┘
                        │
┌─ 层 2 · unit 内解析（每 30 帧一个 unit）───────────────────┐
│  对每个低置信候选，计算：                                    │
│    ① unit 内位移（窗口级聚合，非逐帧）                        │
│    ② 与 anchor 的关系（最近类别、距离/框高、中心是否落入）    │
│    ③ 形状/颜色稳定性（宽高比标准差、色度方差）                │
│  判定为人 ⇔ 有位移 且 不隶属于任何 vehicle anchor             │
│  判定为非人 ⇔ 静止 且（与 vehicle 高重叠 或 邻 tree/wall）    │
└────────────────────────────────────────────────────────────┘
                        │
┌─ 层 3 · 锁存与序列判定（跨 unit）──────────────────────────┐
│  任一 unit 判为人 → 锁 ID（identity latch）                  │
│  之后**不再重判 personhood**，只累积 FALLEN 风险              │
│  复用现有 RiskEngineV2（danger_confirmed 已是同类机制）       │
└────────────────────────────────────────────────────────────┘
```

### 3.1 为什么层 3 是解决 pd4 的关键

pd4 里老人被 YOLO-World 的 `person` 检出的时间分布：

| 帧段 | 状态 | `person` 检出 |
|---|---|---|
| 90–130 | 站立/行走 | ✅ 0.46–0.68 |
| **140–170** | **跌倒过程 / 躺地（被车遮挡）** | ❌ **无** |
| 180–230 | 撑地、试图起身 | ✅ 0.18–0.40 |
| 250–290 | （另一个人，远处） | 0.14–0.29 |

**只要在 90–130 那段锁住身份，140–170 的四帧空档就不影响报警** —— 这正是
"不再每 unit 识别 object"的意义。

## 4. 前置验证：YOLO-World 实测数据

> 模型 `yolov8s-worldv2.pt`，`conf=0.10`，MPS。
> 口径提醒：这是无质量门的原始输出，与 YOLO-Pose 的 `conf=0.02` + 质量门**不完全对等**，
> 只能看方向。

### 4.1 anchor 层可用性（pd4 帧 185）

| 类别 | 分数 | bbox | 尺寸 |
|---|---|---|---|
| **motorcycle** | **0.792** | (374,493,828,975) | 454×483 |
| road | 0.441 | 全画面 | — |
| **person** | **0.280** | **(782,469,975,613)** | 194×145 |
| motorcycle | 0.213 | (349,85,561,463) | 211×378 |

**`person` 那条 (782,469,975,613) 正是 YOLO-Pose 给不出框的位置** —— 说明"老人检不出"
是 pose 模型特有的问题，不是场景里检不出人。

### 4.2 姿态词表显著提升躺地检出

| 帧 | `person` | `person sitting on the ground` |
|---|---|---|
| 140 | 无 | 无（只有右边缘伪框） |
| 150 | 无 | 无（只有边缘伪框） |
| 160 | 无 | 0.11 (756,470,955,585) |
| 170 | 无 | 0.14 (779,456,970,598) |
| **185** | 0.28 | **0.67 (781,469,974,613)** |
| **210** | 0.35 | **0.90 (782,467,972,612)** |

### 4.3 非人素材上的假阳性大幅下降

| 素材 | YOLO-Pose 检出帧占比 | YOLO-World `person` 帧占比 | 车辆类命中率 |
|---|---|---|---|
| `ebicycle`（车罩电动车） | 88.9% | **43.9%** | 98.6% |
| `home` | 57.1% | **0.0%** | 0.0% |
| `wall_mirror` | 33.1% | **0.0%** | 0.0% |
| `car_park` | 30.9% | **9.6%** | 81.9% |

**anchor 层把"车"从"人"里分出来了** —— 这正是现有链路缺的那一维信息。

## 5. 特征清单

### 5.1 anchor 特征（每个 anchor 一份）

| 特征 | 计算方式 | 用途 |
|---|---|---|
| 类别 | YOLO-World 输出 | 语义锚点（vehicle = 强非人证据） |
| bbox | 模型输出 | 空间关系 |
| 帧内归一化位置 | `center / (帧宽, 帧高)` | "在路中间 / 路边" |
| 宽高比 | `w / h` | 形状规则性（树 vs 车） |
| 填充率 | 关键点包围盒面积 / bbox 面积 | 形态贴合度 |
| 框内色度均值/方差 | HSV 的 H 圆均值 + S 方差 | "颜色变化多" |
| 框内边缘密度 | Sobel 幅值 > 阈值 的像素占比 | 纹理规则性 |

### 5.2 unit 特征（每个候选在每个 unit 一份）

| 特征 | 来源 | 备注 |
|---|---|---|
| 位移总和 / 框高 | 现有 `vel` 累积 | **无需新数据** |
| 静止帧占比（\|Δcenter\| < 1px） | track 质心历史 | **无需新数据** |
| 宽高比标准差 | bbox 历史 | 需记录 bbox |
| 与最近 anchor 的类别 | 层 0 | — |
| 与最近 anchor 的距离 / 框高 | 层 0 | 尺度不变 |
| 候选中心是否落入某 vehicle anchor | 层 0 | **比 IoU 更容忍遮挡** |
| 色度方差的时间标准差 | 像素统计 | 需新抽取 |

> ⚠️ **遮挡的处理**：pd4 里老人被电瓶车部分遮挡，IoU 会失效。
> 关系判断必须用"中心落入 anchor 内部"这类松弛判据，不能用 IoU 阈值。

### 5.3 不需要新增的特征

| 看似需要 | 为什么不需要 |
|---|---|
| "30 帧是否在动" | `vel`/`acc` 已完整表达（窗口 192 维 = pos + vel + acc） |
| 绝对位置 | 逐帧差分后已隐含；且 §9.6 指出绝对尺度应丢弃，只在 anchor 关系里用**归一化**位置 |
| 目标类别标签进入分类头 | 层 2 用规则即可，不必重训 |

## 6. 延迟预算

| 组件 | 单帧 | 频率 | 摊销 |
|---|---|---|---|
| YOLO-Pose | 28 ms | 每帧 | 28 ms |
| **YOLO-World** | **41 ms** | **每 5 帧** | **8.2 ms** |
| 层 2 规则计算 | < 1 ms | 每 unit | ≈ 0 |
| **合计** | | | **≈ 36 ms → 27 fps** ✅ |

> anchor 每 5 帧一次的依据：车、树、路面**都是静止的**，5 帧（0.2 s）内不会变化。
> 若场景内有高速运动物体（行驶中的车），anchor 需按类别区分刷新频率。

## 7. 风险与未解问题

| # | 风险 | 严重度 | 缓解 |
|---|---|---|---|
| 1 | **"静止 ⇒ 非人"会误杀"跌倒后不动/昏迷"的人** | 🔴 高 | 只能作为特征给模型/规则组合，**严禁单独作为硬门**；必须靠层 3 在跌倒那一刻锁存 |
| 2 | `ebicycle` 仍有 43.9% 的帧出 `person` 框 | 🟠 中 | 提高 conf + 层 2 的 vehicle 关系过滤 |
| 3 | pd4 帧 140–150 三路都检不到 | 🟠 中 | 靠层 3 延续；或加"person lying"词表 |
| 4 | anchor 检测器自身在夜间会误检（COCO 在车棚） | 🟠 中 | anchor 也需置信度分档 + 时间稳定化 |
| 5 | 关系判断在部分遮挡下失效 | 🟠 中 | 用"中心落入"而非 IoU；用相对位置而非绝对距离 |
| 6 | 多了一个模型 → 依赖、许可、维护面扩大 | 🟡 低 | YOLO-World 在 ultralytics 内，无新框架依赖 |
| 7 | 规则阈值（位移、色度方差）怎么定 | 🟠 中 | 先在离线原型上用现有素材调，不引入训练 |
| 8 | 手头素材里"真人在静止场景"的样本少 | 🟠 中 | 现有 4 段非人素材 + pd1–4 + Le2i 只有 11 段，规则可能过拟合 |

## 8. 已确认的决策

| 决策 | 结论 |
|---|---|
| 落地方式 | **先把设计与验证数据写成文档，再决定实现**（本文） |
| anchor 层频率 | **每 5 帧**（≈8.2 ms 摊销，25 fps 可行） |
| 词表 | `person` + 姿态词（`lying on the ground` / `sitting on the ground` / `walking`）+ 场景词（`road` / `sidewalk` / `tree` / `motorcycle` / `bicycle` / `wall`） |
| 是否需要重训 | 层 0–2 为检测/规则层，**不改分类器输入 → 不需要重训** |
| 层 3 实现 | 复用 `RiskEngineV2` 的锁存模式，新增独立的 identity latch，不改现有状态机 |

## 9. 验收指标与实验方案

### 9.1 指标

| 指标 | 生产基线 | 目标 |
|---|---|---|
| pd4 track 数 | **45** | **≤ 8** |
| pd4 首个 DANGER | 107（但来自电瓶车 track） | ≤ 107，且来自**人**的 track |
| pd4 跌倒段是否被识别为人 | 否（靠假轨迹） | **是** |
| 非人素材每帧假 track 数（`ebicycle`） | 1.6 | ≤ 0.5 |
| 正常 Le2i 7 段 | 全 0 | 全 0 |
| 首 DANGER（跌倒 Le2i 5 段均值） | 178.2 | ≤ 190 |
| 总延迟 | 28 ms | ≤ 40 ms |

### 9.2 素材

| 组 | 用途 | 规模 |
|---|---|---|
| pd1–pd4、stair1–2 | 真实场景召回 | 6 段 / 5373 帧 |
| 非人素材 4 段 | 假阳性 | 4 段 / 5521 帧 |
| 正常 Le2i 7 段 | 误报守门 | 5655 帧 |
| 跌倒 Le2i 5 段 | 报警延迟 | 1514 帧 |
| **人造"静止跌倒"用例** | 风险 1 的守门 | 从 pd4 跌倒后段截取，制造"倒地不动" |

### 9.3 实验顺序（建议）

1. **只做层 0**：YOLO-World 每 5 帧，统计 anchor 集合的稳定性（类别/位置抖动），确认 anchor 可用
2. **层 0 + 层 1**：用 anchor 过滤 pose 候选，量 track 数下降多少
3. **加层 2**：unit 内运动 + 关系规则，量老人是否在任一 unit 被救出
4. **加层 3**：锁存，量首 DANGER
5. 全量对照 §9.1

**每一步都先离线跑，不改进生产代码。**

## 10. 影响面

| 文件 | 改动 |
|---|---|
| `pose/scene_anchors.py` | **新增**。YOLO-World 封装，每 5 帧产出 anchor 集合，含外观/形状统计 |
| `pipeline/object_resolver.py` | **新增**。层 2 的 unit 内判定（运动 + 关系 + 形状/颜色） |
| `realtime_detect.py` | 编排三层；层 3 的 identity latch 状态 |
| `tracker/person_tracker.py` | 可能新增"anchor 绑定"字段（不改匹配逻辑） |
| `pose/pose_extractor.py` | **不动**（避免影响训练缓存一致性，见 [quality-gate §8.1](quality-gate.md)） |
| `pipeline/risk_engine_v2.py` | **不动** |
| `classifier/*` | **不动** |
| `scripts/build/*` | **不动**（本设计不需要重建数据集） |

> 这是一个关键的工程优势：**整条链路不需要重抽关键点缓存、不需要重训**。
> 因此可以快速迭代规则，而不必每次付 2 小时的代价。

```bash
# YOLO-World 在 pd4 上的场景锚点（帧 185）
YOLO_CONFIG_DIR=/tmp/Ultralytics python - <<'PY'
from ultralytics import YOLOWorld
import cv2
cap = cv2.VideoCapture(
    "/Volumes/media-backup/AI-data/real-resource/Yolo_video_resource/"
    "person_fall/person_falldown-4.mp4")
for _ in range(186): ok, frame = cap.read()
cap.release()
m = YOLOWorld("yolov8s-worldv2.pt")
m.set_classes(["person", "person sitting on the ground", "person lying on the ground",
               "motorcycle", "tree", "sidewalk", "road", "wall"])
r = m(frame, verbose=False, conf=0.10)[0]
for b, c, s in zip(r.boxes.xyxy.cpu().numpy(),
                   r.boxes.cls.cpu().numpy(),
                   r.boxes.conf.cpu().numpy()):
    print(m.names[int(c)], round(float(s), 3), [int(v) for v in b])
PY
```

> 必须用 `VideoCapture` 逐帧读（本轮踩过）。

### 逐 track 诊断（pd4 的 45 条 track 来自这个探针）

再按 `cv2.putText` 的 `"Frame: N"` 对齐帧号 —— 与
[eval_pipeline_regress.py](../scripts/eval/eval_pipeline_regress.py) 的 spy 方式相同，
